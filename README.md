# Valhalla 무한매수 전술 관제소 V4.0

## 파일 구성

| 파일 | 역할 |
|---|---|
| `valhalla.py` | Streamlit 화면 (7개 페이지) · 저장소 · 시세 조회 |
| `valhalla_core.py` | 계산 로직 (평단·손익, 키움 파서, 지표, AI 엔진, 백테스트, 유전 알고리즘, 리그, 검증) |
| `jobs/daily_league.py` | 리그 자동 실행 스크립트 (GitHub Actions) |
| `jobs/daily_signals.py` | 신호 관제 매일 자동 점검: 주 1건 예측 기록·채점·섹터별 비교 저장 (GitHub Actions, KST 화~토 07:30) |
| `.github/workflows/daily_league.yml` | 매일 KST 화~토 07:10 자동 실행 |
| `.streamlit/config.toml` | 다크 테마 |
| `requirements.txt` | 배포용 패키지 |
| `tests/` | 자동 테스트 (배포에는 필요 없음) |

**`valhalla.py`와 `valhalla_core.py`는 반드시 같은 폴더에 있어야 합니다.**

## 배포 (Streamlit Community Cloud)

1. 위 파일들을 GitHub 저장소에 올립니다 (`tests/`는 선택).
2. 메인 파일을 `valhalla.py`로 지정합니다.
3. Supabase를 쓰면 Secrets에 기존과 똑같이 입력합니다.
   ```toml
   SUPABASE_URL = "https://xxxx.supabase.co"
   SUPABASE_KEY = "..."
   ```

## 동작 규칙 요약

- **평단:** 이동평균 원가법을 씁니다. 부분 매도 시 평단은 그대로 두고 원가만 비례해서 줄입니다. 전량 매도하면 사이클이 새로 시작됩니다.
- **AI 매매 규칙:** 훈련, 리그, 대시보드 모두 같은 규칙입니다.
  - 매수: 전일 종가 × (1 − 할인율) 지정가
  - 매도: 평단 × (1 + 목표수익률) 지정가
  - 분할 횟수와 예산 한도를 지키며, 수수료를 반영합니다.
- **도달 확률:** 공식으로 만든 '승률'이 아닙니다. 최근 5년 실제 차트에서 같은 상승폭에 기간 내 도달한 비율(경험적 확률)입니다.

## 리그 자동 실행 (GitHub Actions)

1. 저장소 **Settings → Secrets and variables → Actions**에 `SUPABASE_URL`, `SUPABASE_KEY`를 Streamlit Secrets와 같은 값으로 추가합니다.
2. **Actions → 발할라 리그 자동 실행 → Run workflow**로 바로 시험할 수 있습니다.
3. 매일 KST 화~토 07:10에 자동으로 실행되며 아래 일을 합니다.
   - 리그 설정(종목·시작일·자본·비용)대로 오늘까지 가상매매를 진행합니다.
   - `ai_ledger`의 해당 종목 장부를 교체합니다.
   - `valhalla_league_daily`에 날짜별 성적을 기록합니다.
   - `valhalla_job_runs`에 실행 결과를 남깁니다.

## 훈련 방식

- 평가 시나리오는 두 종류입니다.
  - 실제 학습 차트: 전체, 앞 절반, 뒤 절반
  - 가상 차트: 학습 기간의 하루 단위 움직임을 블록째 재표집해 처음부터 새로 만든 차트
- 가상 차트를 실제 차트 뒤에 이어 붙이지 않기 때문에, 특정 상승장 하나를 외우는 과적합이 줄어듭니다.
- 적합도 = (평균 수익 + 최악 시나리오 수익) ÷ 2 − 낙폭 페널티 × 평균 MDD

## 요원 검증

- **배치 전 (훈련소)**
  - 학습에 쓰지 않은 검증 구간 수익이 0보다 커야 합니다.
  - 기간별 안정성(6개월 구간)에서 수익을 낸 구간 비율이 50% 이상이어야 합니다.
  - 검증 구간 낙폭(MDD)이 그냥 보유했을 때보다 작아야 합니다.
  - 학습→검증 성적이 100%p 넘게 떨어지면 과적합 참고 경고를 붙입니다.
  - 기본 설정은 통과한 요원만 배치하는 것입니다.
- **배치 후 (리그)**
  - 리그는 배치일부터 시작합니다.
  - 20거래일을 관찰한 뒤 판정합니다.
    - ✅ 정상: 보유(Buy & Hold) 대비 −10%p 이내
    - ⚠️ 주의: 그 밖의 경우
    - ❌ 교체 권고: 손실 중이면서 낙폭이 허용치(훈련 검증 MDD의 1.5배, 최소 30%)를 넘은 경우

- **과최적화 점검:** 최근 2년은 확률 계산에 쓰지 않는 검증 구간으로 따로 보여 줍니다.

### 처음 한 번: Supabase 테이블 만들기 (SQL Editor)

`valhalla_signal_reports`(매일 비교 스냅샷)도 필요합니다. 구조는 `jobs/daily_signals.py`와 `valhalla_core.REPORT_MAP` 참고.

```sql
create table if not exists valhalla_predictions (
  id bigserial primary key,
  week date not null,
  ticker text not null default 'SOXL',
  created_at timestamptz default now(),
  close double precision, chart_score int, macro_score int,
  signals text, macro_signals text,
  p_up_4w double precision, base_4w double precision, n_4w int,
  p_up_12w double precision, base_12w double precision, n_12w int,
  ret_4w double precision, ret_12w double precision,
  unique (week, ticker)
);
```

다른 테이블에 RLS 정책을 쓰고 있다면 이 테이블에도 같은 정책을 추가하세요.
대상 종목은 기본으로 `valhalla_core.SECTOR_GRID`의 13개 섹터 × (3배·2배·1배 ETF·개별 종목) 53개입니다 (반도체·나스닥100·S&P500·기술·금융·헬스케어·바이오·소형주·산업재·부동산·유틸리티·에너지·금광). 섹터나 유형이 다르면 확률·적중률을 섞지 않고 따로 계산합니다. 바꾸려면 워크플로에 `SIGNAL_TICKERS` 환경변수(예: `SOXL:SOXX,TQQQ:QQQ`)를 추가합니다.

  1. **학습 구간**(최근 2년 제외)으로만 가장 좋은 후보 1개를 고릅니다.
  2. 고를 때 쓰지 않은 **최근 2년**에서 지금 규칙보다 확실히 나을 때만 제안합니다
     (평소보다 나은 종목 비율 +10%p 이상, 평균 적중률 차이 +3%p 이상, 신호 30건 이상, 낙폭 악화 5%p 이내, 후보 자체가 절반 이상 종목에서 평소보다 나음).
  3. 제안은 `valhalla_signal_rules`에 '승인 대기'로 기록되고, 신호 관제 화면에서 **적용 / 경쟁시키기 / 거절**을 직접 누릅니다.
- **챔피언 vs 도전자:** '경쟁시키기'를 누르면 지금 규칙(챔피언)은 그대로 두고, 도전자 규칙의 신호도 매일 `valhalla_rule_signals`에 실전으로 기록·채점합니다(최대 3개). 도전자가 매수 채점 20건·서로 다른 8주 이상에서 챔피언보다 적중률 +10%p 이상이면 '승격 추천'이 뜨고, 승격은 직접 누릅니다.
- 후보 선정에 '신호가 난 서로 다른 주 수'(검증 구간 8주 이상) 조건이 있어, 몇 번의 시장 반등에 몰린 규칙은 걸러집니다.
- 매일 자동 점검은 항상 '사용 중' 규칙으로 계산하고, 결과에 규칙 버전을 함께 저장합니다.

## 선수 경기장 (모든 선수를 같은 방식으로 채점)

- 모든 선수가 매주 종목별 **비중(0~1)** 을 내고, 다음 주 실제 수익률로 똑같이 채점합니다 (`valhalla_positions`).
- 선수: 대표 규칙·도전 규칙, **추세 필터**(같은 섹터 1배 ETF가 200일선 위면 보유), **변동성 조절**(평소 변동성 ÷ 최근 20일 변동성), **그냥 보유**, **AI 위원회**(Claude 예약 작업, 매주 토요일 10개 종목, 회의록은 `valhalla_council_minutes`), **앙상블**.
- 앙상블 가중치: 이번 달 1일 이전 채점 기록만 사용(월 1회 변경), 최근 26주 보유 대비 초과수익 기반, 20주 미만이면 균등, 절반은 균등과 섞고 한 선수 최대 50%. 결과가 나오기 전인 주에만 계산해 미래 정보 누수가 없습니다.
- **매매기법 연구소 선수**(레버리지 ETF에서만): ① 내 방식(40분할·+10% 전량익절), ② V2형(별지점·1/4 분할익절), ④ V2+쿼터손절+200일선, ⑥ 50:50 리밸런싱. 연구소 백테스트 엔진과 같은 규칙으로 2016년부터 일봉 계좌를 굴려, 매주 금요일 종가의 투자 비중을 냄.
- **찰스 SOXL 시스템**(레버리지 ETF에서만, TradingView 공개 스크립트 v5 이식): 같은 섹터 1배 ETF가 200일선 +2% 위이고 변동성이 낮으면 70% 보유, 과열(+25%)이면 35%, 깨지면 0. 큰 규칙이 쉴 때만 단기 추세(25%)·급락 반등(15%). 신호 다음 날 종가 체결.
- **반등 판별전**: SOX가 고점 대비 15% 넘게 빠진 상태에서 하루 +5% 또는 20일 저점 대비 +15% 반등하면 사건. 그 주 금요일 선수별 SOXL 비중을 '추세 전환 확률'로 보고, 13주 안에 직전 저점을 깨면 일시 반등, 안 깨고 13주 뒤 더 높으면 추세 전환으로 채점(브라이어). 기준 선수는 과거 사건의 추세 전환 비율. 과거 사건으로 연습 경기, 2026-11-16 이후는 실전(`valhalla_rebound_events`).
- **반등 체크리스트**(시장 레이더): 10년물 금리(4.5%·한 달 방향), VIX(30), 신용 스프레드 BAA−10년물(3개월 방향), 하이일드 스프레드(4%, 표시용), 근원 PCE(표시용) + 일정 달력(`EVENT_CALENDAR`, 미확정 표시). 같은 4조건으로 반등 판별전 선수 '거시 체크리스트'(확률 0.2+0.6×충족/4)가 1994년부터 채점됨. 실전 값은 `valhalla_rebound_events.macro_prob`.
- **일봉 리그**: 모든 선수가 매일 장 마감 비중을 내고 다음 거래일 수익률로 채점(`valhalla_daily_positions`, 2026-11-24부터). 규칙은 일봉 버전, 추세 필터·변동성 조절은 매일 계산, 레버리지 ETF는 연구소 기법·찰스 시스템이 원래 방식대로 매일. 신호 관제에 오늘 비중·신호 표, 경기장에 '일봉 리그' 탭.
- **일봉 버전 규칙**: 같은 규칙을 매일 '오늘로 끝나는 최근 5거래일'에 적용(5개 위상의 5거래일 묶음을 날짜순으로 합침, 'n주 연속'은 5거래일 간격). 신호 관제에 오늘의 일봉 신호 카드, 과거 성적 탭에 주봉 vs 일봉 일 단위 비교(`backtest_daily`). 실전 장부에는 기록하지 않음.
- **경기장 챔피언**: 규칙·기준 선수·AI 위원회·앙상블 누구나 챔피언이 될 수 있음. 챔피언과 같은 종목·같은 주로 20주 이상 맞대결해 누적 수익이 3%p 이상 높고 최대 낙폭이 5%p 넘게 나쁘지 않으면 '승격 추천', 올리기는 사람이 버튼으로 결정. 대표 규칙이 바뀌면 (챔피언이 옛 규칙이었을 때) 자리를 이어받음. 테이블 `valhalla_arena_champion`.
- 화면: 신호 관제 → 선수 경기장 (실전 경기표 · 계산 가능한 선수의 과거 성적 · AI 위원회 회의록).
